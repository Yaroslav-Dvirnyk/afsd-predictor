## Задача 1. Честно подписать ширину валика `w`

**Причина.** В безбуртовой схеме ширина валика `w` **не влияет на температуру**.
Она входит только в `H = πR²·v_f/(w·v_t)`, а `H` в физической модели —
результат, а не вход (в тепловой баланс входит объёмный расход `πR²v_f`,
не зависящий от того, во сколько материал растечётся). `H` влияет на
температуру только в старой эмпирической ветке с коэффициентом `C_emp`
(`geom2` в `afsd_core.py`) и в схеме с плечом, где задаёт `R_eff`.

Сейчас подпись галочки — просто «учесть w:», и по ней невозможно понять,
на что это влияет. Пользователь может крутить `w`, ожидая изменения
температуры, и не понимать, почему ничего не меняется.

**Что сделать.**

1. В `afsd_core.py`, строка ~486, в словаре переводов заменить:

```python
"chk_beadw": dict(uk="врахувати w:", ru="учесть w:", en="use w:"),
```

на

```python
"chk_beadw": dict(uk="врахувати w (лише для H):",
                  ru="учесть w (только для H):",
                  en="use w (affects H only):"),
```

2. Если в этом же файле есть отдельный словарь для китайского (`zh`),
   добавить туда соответствующий ключ по образцу соседних строк.

3. В `afsd_predictor.py`, строка ~1737, в строке результата пометить,
   что `H` и `w` — геометрия, а не вход теплового расчёта:

```python
            extra += f"   H={H:.2f} мм   w={wb_used:.2f} мм"
```

заменить на

```python
            extra += f"   [геометрия] H={H:.2f} мм   w={wb_used:.2f} мм"
```

4. Рядом с блоком добавить короткий комментарий:

```python
        # H и w — ВЫХОД баланса в безбуртовой схеме: в тепловой расчёт входит
        # объёмный расход подачи πR²v_f, а не сечение валика. Влияют на T только
        # в старой эмпирической ветке (C_emp) и в схеме с плечом (через R_eff).
```

**Ничего не удалять.** Поле `w` нужно как диагностика: сравнив расчётную `H`
с измеренной высотой валика, пользователь проверяет собственные входные данные
(подачу, траверс, диаметр). Именно так была поймана ошибка с диаметром в одном
из валидационных случаев.
